## 1. 文档信息与核心决策

### 1.1 产品名称建议

CamPush / 即推 / 双摄直播助手。

### 1.2 一句话定位

打开 App 即可推流的 Android 原生工具。支持单前置、单后置或前后同时推流；默认采用效果最优的推流协议；推流成功后只生成一个可直接打开的播放地址，复制即可观看。

### 1.3 核心决策

1. **推流协议只列推流协议**：WebRTC（WHIP）、SRT、RTMP。HLS、HTTP-FLV 不作为推流协议，只作为播放页内部的播放兼容能力。
2. **对外只输出一个播放地址**：标准模式下，复制、二维码、分享均使用同一个 H5 播放页 URL，不暴露多个协议地址。
3. **播放页内部自适应**：公网模式播放页优先 WebRTC 播放，失败降级 HTTP-FLV，最后 HLS 兜底；用户无需选择播放协议。
4. **服务端能力分两种场景**：仅局域网模式由客户端内置端侧服务完成；公网可访问模式依赖云端服务端。
5. **客户端增加“访问范围”场景开关**：开始推流前二选一，推流中锁定；切换需停止推流，旧地址失效。
6. **公网模式推流协议切换时播放地址不变**：由服务端切源，播放页自动重连。
7. **停止推流后播放地址失效**：地址带短时 token，可选观看口令。
8. **双路独立推流为专业模式例外**：会明确提示生成两个地址，不影响标准模式“一个地址”的承诺。

## 2. 产品定位与目标用户

### 2.1 核心价值

- **极简上手**：已授权用户从打开到开始推流 ≤ 10 秒。
- **效果优先**：推流协议按观看体验排序，默认 WebRTC。
- **灵活采集**：支持单摄与真正的前后双摄同时推流。
- **一个地址即看**：播放页自动选择最佳播放方式，用户不需要理解协议。
- **双场景可选**：局域网零服务端成本；公网依赖云端服务，保证异地可看。
- **兜底可靠**：公网播放页内部保留 HLS 兜底，但不额外提供第二个地址。

### 2.2 目标用户

- 需要快速共享实时画面的个人用户：远程协助、家庭监控、临时直播。
- 中小团队教学、活动直播。
- 同一局域网内的临时共享场景：家庭、教室、会议室、手机热点。
- 开发者与测试人员验证推拉流链路。

### 2.3 典型使用场景

| 场景 | 推荐访问范围 | 说明 |
|---|---|---|
| 家庭监控、同一 Wi-Fi 查看 | 仅局域网 | 无需云端，隐私优先 |
| 教室/会议室临时投屏 | 仅局域网 | 同一网络浏览器打开地址 |
| 远程协助、异地观看 | 公网可访问 | 需要云端服务端和公网播放地址 |
| 活动直播分享给外部人员 | 公网可访问 | 一个播放页地址，可复制分享 |
| 开发者链路验证 | 两种均可 | 局域网验证端侧服务，公网验证云端闭环 |

## 3. 核心概念与产品约束

### 3.1 推流协议与播放协议分离

- **推流协议**：App 到媒体接入端的协议，包括 WebRTC（WHIP）、SRT、RTMP。
- **播放协议**：播放页到观看端的协议，包括 WebRTC、HTTP-FLV、HLS；由播放页内部自动选择。
- HLS、HTTP-FLV 不出现在推流协议设置中。

### 3.2 一个播放地址原则

标准模式下，推流成功后只展示一个播放地址：

```text
https://play.example.com/s/{roomId}?token=xxxx
```

该地址是 H5 播放页 URL，不是裸流地址。播放页内部完成协议自适应和 HLS 兜底。

局域网模式下同样只输出一个地址：

```text
http://{局域网IP}:{端口}/s/{token}
```

### 3.3 服务端能力边界

- **仅局域网模式**：服务端能力内置于 Android 客户端，端侧完成媒体分发和播放页响应；不承诺公网可达、HLS 兜底和多观看者弹性扩展。
- **公网可访问模式**：依赖云端服务端完成推流接入、转封装、WebRTC 播放、HLS 兜底、鉴权与地址生命周期；纯客户端无法替代 NAT 穿透和 TURN 中继。

### 3.4 标准模式与专业模式

- **标准模式**：单路合成画面，一个播放地址。
- **专业模式**：双路独立推流、多地址推流、BYO 自定义推流地址。会明确提示可能产生多个地址或由用户自有服务端提供播放能力，不影响标准模式承诺。

## 4. 访问范围场景开关

### 4.1 开关定义

**名称**：访问范围
**控件**：分段选择器，位于主界面「开始推流」按钮上方，或设置页“服务器与地址”分组。
**选项**：

| 选项 | 标识 | 说明 |
|---|---|---|
| **仅局域网** | LAN | 端侧完成服务端功能，同一 Wi-Fi/热点下可看 |
| **公网可访问** | WAN | 依赖云端服务端，公网任意设备可看 |

### 4.2 默认与切换规则

- 首次启动默认 **公网可访问**，保证“复制地址即可看”的核心承诺。
- 公网服务未配置、无网络或额度不足时，公网选项置灰并提示，引导切换“仅局域网”。
- 开始推流前可切换；推流中开关置灰，点击提示“请先停止推流后切换访问范围”。
- 切换访问范围会改变播放地址，必须明确提示旧地址失效。
- 主界面顶部状态栏显示当前模式标签：`局域网` / `公网`。

### 4.3 两种模式能力对比

| 能力 | 仅局域网模式 | 公网可访问模式 |
|---|---|---|
| 服务端位置 | 客户端内置端侧媒体服务 | 云端服务端 |
| 推流接入 | 端侧本地服务/本地直出 | 云端 WHIP/SRT/RTMP 接入 |
| 播放地址 | `http://局域网IP:端口/s/{token}` | `https://play.example.com/s/{roomId}?token=...` |
| 播放协议 | 播放页内部优先低延迟方式，降级 HTTP-FLV/MJPEG | 播放页内部 WebRTC → HTTP-FLV → HLS 兜底 |
| 公网可达 | 不支持 | 支持 |
| 观看条件 | 同一局域网/热点，且未被 AP 隔离 | 任意公网设备，凭地址和 token |
| HLS 兜底 | 不承诺 | 提供，播放页内部兜底 |
| 多观看者 | 受手机上行带宽和 CPU 限制，MVP 建议 1–3 人 | 由云端弹性扩展，按套餐/额度限制 |
| 鉴权 | 端侧短时 token、可选 PIN | 云端短时 token、可选观看口令 |
| 停止失效 | 端侧服务停止，地址失效 | 服务端销毁房间，地址失效 |
| 依赖 | 无云端服务；需同一局域网 | 必须依赖云端服务端 |
| 适用场景 | 家庭监控、教室、同一 Wi-Fi 临时共享、隐私优先 | 远程协助、异地观看、活动直播、分享给外部人员 |

### 4.4 局域网模式产品承诺与限制

**承诺**：
- 无需云端服务端，一个 Android 端完成采集、编码、端侧服务与播放页分发。
- 同一 Wi-Fi/热点下，另一台设备通过浏览器打开唯一地址即可观看。
- 支持短时 token、可选 PIN、停止即失效。
- 播放页内部优先低延迟方式，失败降级 HTTP-FLV/MJPEG。

**必须明示的限制**：
- 仅限同一局域网，跨公网不可访问。
- 若路由器开启 AP 隔离，观看设备可能无法访问，需提示检查网络。
- 手机作为服务端，并发观看数受上行带宽和性能限制，MVP 限制 1–3 个观看者并提示。
- 不承诺 HLS 兜底；HLS 兜底仅公网模式提供。
- 手机热点场景可用，但需提示观看设备连接该热点。

### 4.5 公网模式产品承诺与限制

**承诺**：
- 对外只输出一个 H5 播放页地址，复制即可在公网打开。
- 播放页内部自适应 WebRTC → HTTP-FLV → HLS 兜底。
- 推流协议切换时播放地址不变，服务端切源。
- 停止推流地址失效，支持短时 token 和可选口令。

**限制**：
- 必须依赖云端服务端，纯客户端无法保证公网可达。
- 需要账号/额度/套餐或 BYO 服务端配置。
- 对称 NAT/CGNAT 下 WebRTC 播放依赖 TURN 中继，属于云端服务能力。

## 5. 摄像头采集模式

### 5.1 三种模式

- **仅后置**：默认模式。
- **仅前置**。
- **前后同时开启（双摄模式）**。

### 5.2 双摄模式规则

- 启动时自动检测设备是否支持 Camera2/CameraX Multi-Camera 前后同时工作。
- 不支持设备：隐藏「前后同时」选项，并提示具体原因。
- 支持设备：默认使用**画中画 PiP 合成单路画面推流**，播放端只需一个地址。
- 合成方式用户可切换：
  - 画中画：后置为主画面，前置为可拖动、缩放小窗；
  - 左右分屏；
  - 上下分屏；
  - 主次画面一键交换。
- 高级选项：双路独立推流。该模式属于专业模式，会明确提示可能生成两个播放地址。
- 性能保护：双摄默认降分辨率、降帧率，实时监控温度与电量，过热自动提示或降级。

## 6. 推流协议定义

### 6.1 推流协议优先级

适用于公网可访问模式。局域网模式端侧服务能力有限，MVP 使用本地直出/端侧 RTMP，后续增强 WebRTC P2P。

| 优先级 | 推流协议 | 延迟 | 标签 | 说明 |
|---|---|---|---|---|
| 1 | **WebRTC（WHIP）** | 200–800ms | 超低延迟 · 推荐 | 默认推流协议，适合实时互动 |
| 2 | **SRT** | 0.5–2s | 弱网高画质 | 强抗丢包，弱网稳定 |
| 3 | **RTMP** | 1–3s | 稳定通用 | 生态成熟，服务端兼容好 |

### 6.2 默认与切换逻辑

- 公网模式首次启动默认 **WebRTC 推流**。
- 设置页只展示上述三个推流协议，按优先级排列，每项显示延迟预估与标签。
- 公网模式下切换推流协议后自动重新推流，但**对外播放地址保持不变**。
- 若当前设备或网络不支持默认协议，自动降级到下一优先级并提示用户。
- HLS、HTTP-FLV 不出现在推流协议设置中。
- 局域网模式 MVP 不支持推流中切换协议；停止后可改，地址重新生成并提示。

## 7. 播放地址与播放页

### 7.1 公网模式播放地址

推流成功后，界面只展示一个“推荐播放地址”：

```text
https://play.example.com/s/{roomId}?token=xxxx
```

操作按钮：
- **复制**：只复制这一个播放地址。
- **二维码**：只指向这一个播放地址。
- **分享**：只分享这一个播放地址。
- **本机预览**：App 内低延迟预览，或打开同一个播放页。

### 7.2 公网播放页内部自适应

播放页按以下顺序自动选择播放方式：

1. 优先尝试 **WebRTC 播放**；
2. WebRTC 不支持或失败时降级 **HTTP-FLV**；
3. HTTP-FLV 失败时降级 **HLS 兜底**；
4. 全部失败展示明确错误与重试按钮。

用户只拿到一个地址，不需要理解播放协议。HLS 仅作内部兜底，不单独提供地址。

### 7.3 局域网模式播放地址

```text
http://{局域网IP}:{端口}/s/{token}
```

- 播放页由端侧 HTTP 服务响应。
- 优先低延迟播放方式，失败降级 HTTP-FLV/MJPEG。
- 支持可选 PIN。
- 不承诺 HLS 兜底。
- 停止推流后端侧服务停止，地址失效。

### 7.4 地址生命周期与安全

- 停止推流后播放地址失效。
- 公网模式推流协议切换时，播放地址不变。
- 播放地址带短时 token，可选观看口令/PIN。
- 推流地址与推流密钥不展示给普通用户，避免泄露。
- 分享时提示“任何拿到链接的人可观看”，必要时启用口令。
- 切换访问范围后旧地址失效，新地址重新生成。

### 8.4 保护能力

- 省电模式一键开启：强制单摄 + 较低码率 + 降分辨率。
- 权限与隐私明确提示。

- 公网额度不足提示与模式引导。

## 9. 完整用户流程

### 9.1 标准流程

1. 打开 App，首次申请摄像头 + 麦克风权限。
2. 进入主界面，默认后置摄像头实时预览。
3. 用户选择摄像头模式、推流协议。
4. 用户选择访问范围：仅局域网 / 公网可访问。
5. 点击底部大按钮「开始推流」。
6. 推流成功后，界面高亮展示**唯一推荐播放地址**，提供复制、二维码、本机播放、分享按钮。
   - 局域网模式提示“仅同一局域网可打开”，展示 PIN（如启用）。
   - 公网模式提示“任何拿到链接的人可观看”，支持口令。
7. 推流中：
   - 公网模式可热切换推流协议，播放地址不变。
   - 局域网模式 MVP 协议锁定，停止后可改。
   - 访问范围开关置灰。
8. 点击停止或从通知栏结束推流，播放地址失效。

核心路径目标：已授权用户从打开到拿到可播放地址 ≤ 10 秒。

### 9.2 局域网模式流程

1. 选择“仅局域网”。
2. App 启动端侧媒体服务，检测局域网 IP。
3. 开始推流，编码流进入端侧服务。
4. 生成 `http://局域网IP:端口/s/{token}`。
5. 另一台同网设备浏览器打开地址观看。
6. 停止推流，端侧服务停止，地址失效。

### 9.3 公网模式流程

1. 选择“公网可访问”。
2. 向云端申请房间与推流密钥。
3. App 使用选定推流协议推流到云端。
4. 云端返回统一播放页地址。
5. 分享/复制/二维码均使用该地址。
6. 停止推流，云端销毁房间，地址失效。

## 10. 界面与交互形态

### 10.1 主界面布局

竖屏优先，完美支持横屏。

- **顶部状态栏**：推流状态、访问范围标签、推流协议、摄像头模式、网络质量、实时码率/帧率、温度/电量提示。
- **中央**：全屏摄像头预览。双摄时显示合成画面，小窗可拖动。
- **开始按钮上方**：访问范围分段选择器（开始前可用，推流中置灰）。
- **底部主操作区**：
  - 超大「开始/停止推流」按钮；
  - 左侧：摄像头模式切换；
  - 右侧：闪光灯、静音、设置。
- **推流成功后**：半透明悬浮卡片固定展示唯一播放地址与操作按钮，可折叠，不遮挡关键预览区域。

### 10.2 设置页关键分组

- **访问范围**：仅局域网 / 公网可访问（默认公网）。
- **推流协议**：WebRTC（默认）、SRT、RTMP，按优先级列表展示。
- **摄像头与双摄**：合成方式、性能模式。
- **画质与性能**：分辨率、码率、帧率、自适应、省电模式。
- **局域网设置**：端侧服务端口、PIN 开关、并发上限提示、网络检测。
- **公网服务**：托管服务状态、额度、自定义服务端地址、推流密钥管理。
- **其他**：水印、录制、日志、关于。

设置页只读说明：

> 播放地址统一生成，播放页会自动选择最佳播放方式；HLS 仅作为公网播放兜底，不单独提供地址。局域网模式仅同一网络可访问。

### 10.3 关键交互细节

- 所有重要状态变化均有明确反馈：成功、失败原因、降级提示。
- 双摄与高优先级协议组合时，首次给出耗电/发热提示。
- 横屏模式下自动适配操作栏位置，适合支架固定拍摄。
- 公网推流协议切换时提示“正在重新连接，播放地址不变”。
- 切换访问范围时提示“需停止推流，旧地址将失效”。

## 11. 技术架构与实现要点

### 11.1 客户端统一能力

- **采集**：CameraX + Camera2，优先使用多摄 API 实现真正前后同时。
- **编码**：MediaCodec 硬编 H.264/H.265 为主，软编兜底。
- **合成**：双摄 PiP/分屏使用 OpenGL ES 本地渲染，默认合成单路推流。
- **保活**：前台服务 + 通知栏，引导加入电池优化白名单。
- **性能**：双摄与 WebRTC 场景下实时监控 CPU、温度、电量，必要时自动降级。

### 11.2 公网模式客户端

- WebRTC 使用 WHIP 推流；
- SRT 使用成熟 SRT 库；
- RTMP 使用稳定 RTMP 推流库；
- 客户端只展示云端返回的统一播放页 URL；
- 协议切换由服务端切源，播放地址不变。

### 11.3 局域网模式客户端

- 内置轻量 HTTP 服务：NanoHTTPD 或同类库，提供播放页、MJPEG/HTTP-FLV 分发、token 校验。
- MVP 使用本地编码直出 + 端侧 HTTP 分发；可选端侧 RTMP 服务。
- 端侧维护房间生命周期、PIN、并发计数、停止失效。
- 播放地址使用当前局域网 IP + 端口 + token；二维码指向该地址。
- 不默认生成 HLS；兼容性兜底使用 MJPEG/HTTP-FLV。
- 可选引入 ZLMediaKit Android 版作为端侧媒体引擎，但需评估 APK 体积、功耗和稳定性，不作为 MVP 默认。

### 11.4 简化架构图

```text
公网模式：
Android App（采集/编码/合成） → WHIP/SRT/RTMP → 云端媒体服务
云端媒体服务 → WebRTC/HTTP-FLV/HLS → 统一 H5 播放页
云端负责：信令、TURN、转封装、HLS切片、token鉴权、房间生命周期

局域网模式：
Android App（采集/编码/合成 + 端侧HTTP服务） → 同一Wi-Fi
观看设备浏览器 → http://局域网IP:端口/s/{token}
端侧负责：播放页、HTTP-FLV/MJPEG分发、PIN/token、并发控制、停止失效
```

## 12. 局域网模式端侧服务模块

### 12.1 模块职责

- 启动/停止端侧 HTTP 服务。
- 响应播放页请求，返回轻量 H5 页面。
- 分发 HTTP-FLV 或 MJPEG 流。
- 校验短时 token 和可选 PIN。
- 维护并发观看计数和上限。
- 停止推流时关闭服务，地址失效。
- 展示当前局域网 IP 和端口，便于排查。

### 12.2 并发与性能

- MVP 建议限制 1–3 个观看者，超过提示“局域网模式并发受限，建议切换公网模式”。
- 实时监控上行带宽、CPU、温度；达到阈值提示或降级。
- 观看者越多，所需上行带宽越高，UI 明示。

### 12.3 网络检测

- 检测是否连接 Wi-Fi/热点。
- 提示 AP 隔离风险。
- 检测 IP 变化，地址变化时提示重新复制。
- 热点场景提示观看设备连接同一热点。

### 12.4 不支持的能力

- 不承诺公网可达。
- 不承诺 HLS 兜底。
- 不承诺大规模并发。
- 不替代 TURN 中继。

---

## 13. 公网模式服务端能力

### 13.1 最小服务端闭环

- WHIP 推流接入；
- SRT/RTMP 推流接入；
- 媒体路由与转封装/转码；
- WebRTC 播放（WHEP）与信令；
- HTTP-FLV 播放；
- HLS 切片兜底；
- TURN 服务；
- 播放地址 token 鉴权与生命周期管理；
- 可选观看口令；
- 房间创建、销毁、额度与套餐管理。

### 13.2 地址与协议切换

- 服务端生成 `roomId`、推流密钥、播放 token。
- App 只展示统一播放页 URL。
- 推流协议切换时，服务端切换播放源，播放页自动重连，地址不变。
- BYO 自定义推流地址模式：App 只负责推流，播放地址由用户自有服务端提供；需明确提示该模式不保证统一播放页体验。

## 14. 边界情况与体验保障

- 设备不支持双摄：优雅隐藏选项并说明原因。
- 公网推流协议不支持或网络差：自动降级并提示，播放地址不变。
- 局域网模式观看设备无法打开：检查同一 Wi-Fi、AP 隔离、防火墙、热点连接。
- 手机热点：提示观看设备连接热点后打开地址。
- 局域网观看者过多：提示达到并发上限，建议切换公网模式。
- 公网额度不足：提示充值/切换 BYO/切换局域网。
- 切换访问范围：必须停止推流，旧地址失效，新地址重新生成。
- 弱网/高丢包：优先依赖 SRT 或 WebRTC 抗丢包能力，开启自适应码率。
- 耗电与发热：提供明显「省电模式」。
- 权限拒绝：清晰引导去系统设置，并说明无法使用的具体功能。
- 播放兼容：公网播放页内部 HLS 兜底，但对外仍只展示一个地址。

## 15. 安全、隐私与合规

- 播放地址带短时 token，停止推流即失效。
- 可选观看口令/PIN。
- 推流地址与推流密钥不展示给普通用户。
- 分享时提示“任何拿到链接的人可观看”。
- 局域网模式提示“同网设备可能访问”。
- 公网服务需考虑内容审核、ICP/等保等合规要求。
- 日志导出需脱敏，不包含推流密钥和完整 token。

## 16. 关键指标与验收标准

### 16.1 核心指标

- 推流成功率；
- 播放页可打开率；
- 首帧时间；
- 端到端延迟估算；
- 卡顿率；
- 协议切换中断时长；
- 双摄温升与降级触发率；
- 崩溃率；
- 地址失效准确率；
- 局域网并发失败率；
- 公网播放页 HLS 兜底触发率。

### 16.2 验收口径

- 已授权用户从点击开始到拿到可访问播放地址 ≤ 10 秒。
- 公网 WebRTC 播放首帧目标 < 2 秒。
- 公网推流协议切换后播放地址不变。
- 停止推流后播放地址不可用。
- 双摄不支持设备不出现不可用选项。
- 局域网模式：同一 Wi-Fi 下另一设备通过浏览器打开唯一地址可播放；停止推流后地址不可用；PIN/token 生效；AP 隔离时有明确错误提示。
- 公网模式：移动网络下打开唯一播放地址可播放；播放页内部可降级 HLS；停止后地址失效。
- 场景开关：开始前可切换；推流中置灰并提示；切换后地址更新且旧地址失效。
- 默认策略：首次启动默认公网；公网不可用时置灰并引导局域网。

## 17. 版本规划

### M0 技术验证

- 验证目标机型双摄并发支持率。
- 验证公网 WebRTC WHIP 推流 + 统一 H5 播放页。
- 验证 RTMP 推流后服务端转 HLS 兜底。
- 验证双摄 PiP 本地合成推单路。
- 验证公网协议切换地址不变。
- 验证局域网端侧 HTTP 服务 + HTTP-FLV/MJPEG 播放。

### M1 可用闭环

- 访问范围开关上线，默认公网。
- 公网模式：WebRTC（默认）、RTMP 推流；唯一 H5 播放地址；播放页 WebRTC 优先、HLS 兜底。
- 局域网模式：基础 HTTP-FLV/MJPEG 端侧服务，token/PIN，并发限制 1–3。
- 单后/单前摄像头。
- 复制、二维码、分享、本机预览。
- 通知栏控制、基础状态指标、停止即失效。

### M2 双摄与增强

- 支持设备上的前后同时 PiP 合成。
- 公网 SRT 推流。
- 公网播放页 HTTP-FLV 降级能力。
- 局域网端侧 WebRTC P2P/本地低延迟播放。
- 局域网并发提示、网络诊断、AP 隔离引导。
- 本机边推边看、录制、水印、多地址推流。

### M3 专业化与商业化

- 更丰富双摄合成方式与双路独立推流。
- 多地址推流、日志导出。
- 简易观众端。
- 云端服务器套餐与账号体系。
- BYO 服务端模式完善。

## 18. 风险与开放问题

### 18.1 主要风险

- **双摄兼容性**：设备厂商多摄并发支持差异大，需白名单和运行时检测。
- **端侧服务功耗与并发**：手机作为服务端受上行带宽、CPU、温度限制。
- **公网成本**：WebRTC SFU、TURN、HLS 转封装带来带宽和计算成本。
- **NAT 穿透**：对称 NAT/CGNAT 下必须依赖 TURN。
- **安全隐私**：公开地址可能被转发，需 token、口令、失效机制。
- **合规**：公网直播涉及内容审核和资质要求。

### 18.2 开放问题

- 默认访问范围是否长期保持“公网可访问”，还是根据网络环境自动推荐。
- 局域网模式是否在 M1 即支持端侧 RTMP，还是仅本地直出 HTTP-FLV/MJPEG。
- 双摄双路独立推流的入口是否放入专业模式二级页面。
- 公网托管服务是自建还是接入第三方媒体云。
- 商业化模式：流量套餐、时长套餐、BYO 免费工具模式。

## 19. 附录：术语表

| 术语 | 说明 |
|---|---|
| WHIP | WebRTC HTTP Ingestion Protocol，WebRTC 推流接入协议 |
| WHEP | WebRTC HTTP Egress Protocol，WebRTC 播放协议 |
| SFU | Selective Forwarding Unit，选择性转发媒体服务器 |
| TURN | Traversal Using Relays around NAT，NAT 中继服务 |
| HLS | HTTP Live Streaming，播放协议，仅公网播放页内部兜底 |
| HTTP-FLV | 基于 HTTP 的 FLV 播放协议，用于播放页低延迟降级 |
| 端侧服务 | 运行在 Android 客户端内的轻量媒体分发与播放页服务 |
| 访问范围 | 仅局域网 / 公网可访问的场景开关 |
| 标准模式 | 单路合成画面，一个播放地址 |
| 专业模式 | 双路独立推流、多地址、BYO 等高级能力，可能产生多个地址 |
